# AI 宠物本地化架构设计

## 目标

围绕需求文档的“纯本地部署、图片上传、本地 AI 生成、全生命周期管理”目标，本项目采用前后端分离但数据闭环在本机的架构。前端只负责交互展示，后端承担上传校验、生成编排、数据持久化、资源管理、互动状态更新和运维状态输出。

## 技术选型

- Web 前端：Vite + React
  - 适合快速构建响应式上传和管理界面。
  - 通过浏览器 File API 做格式、大小和有效图片预检。
- 本地后端：Node.js + Express
  - 本地部署简单，Windows 和 Linux 兼容。
  - 通过 `multer` 接收单图上传。
- 本地数据库：Node.js 内置 `node:sqlite`
  - 不依赖外部数据库服务。
  - 支持本地持久化、事务和快速查询。
- 本地 AI 模型适配层：`server/services/localAiModel.js`
  - 当前实现为离线模拟模型：读取图片字节、做基础有效性校验、基于哈希提取稳定特征、生成 SVG 虚拟宠物资源。
  - 真实模型接入时保留同一接口：`analyzeAndGenerate({ filePath, mimeType, originalName })`。

## 模块边界

### 前端

- 图片选择和预览。
- 文件格式、大小、图片可解码校验。
- 生成进度展示。
- 宠物列表、详情、删除。
- 喂食、陪伴、游戏互动。

### 后端 API

- `GET /api/health`：服务、模型、存储健康状态。
- `GET /api/pets?userId=demo-user`：查询用户宠物。
- `POST /api/pets`：上传图片并生成宠物。
- `DELETE /api/pets/:petId?userId=demo-user`：删除宠物和本地资源。
- `POST /api/pets/:petId/interactions`：互动并更新状态。

### 本地 AI 层

当前 MVP 不调用任何云端模型，所有逻辑在本地完成。真实生产模型建议拆成三个子模块：

1. 视觉校验：宠物主体检测、清晰度、遮挡、图片有效性。
2. 特征提取：品类、毛色、纹理、体态、五官、轮廓。
3. 资源生成：2D/3D 形象生成、渲染、资源标准化。

### 数据层

核心表：

- `pets`：宠物基础数据、特征 JSON、状态 JSON、资源路径、归属用户。
- `audit_logs`：上传、生成、删除、互动操作留痕。

## 数据流

1. 用户选择图片。
2. 前端完成格式、大小和可解码校验。
3. 前端上传到本地后端。
4. 后端写入临时文件并做服务端校验。
5. 本地 AI 适配层分析图片并生成资源。
6. 后端写入 SQLite，并删除临时原图。
7. 前端展示生成结果并进入宠物管理/互动状态。

## 隐私与安全

- 不调用任何外部 AI 或云端接口。
- 上传原图默认只在 `storage/uploads` 临时存在，生成完成或失败后清理。
- 只持久化特征 JSON、状态 JSON 和虚拟宠物资源。
- 删除宠物时同步删除本地生成资源。
- 所有关键动作写入 `audit_logs`。

## 后续真实 AI 接入建议

- 将 `localAiModel.js` 替换为 Python/ONNX Runtime/本地推理服务调用。
- 保持输出结构不变，避免改动业务 API：
  - `species`
  - `appearance`
  - `confidence`
  - `asset`
- 增加 GPU/CPU 推理队列和模型版本表。
- 增加 SSE 或 WebSocket 进度流，用于真实模型多阶段进度反馈。
