# 实施路线图与任务拆解

## 1. 总体里程碑

| 阶段 | 周期建议 | 目标 | 交付 |
| --- | --- | --- | --- |
| M0 | 2-3 天 | 项目初始化和设计确认 | 技术方案、视觉方向、数据模型 |
| M1 | 1-2 周 | Web MVP | 首页、生成工作台、作品库、mock 订单 |
| M2 | 1-2 周 | 生成服务闭环 | 候选图生成、任务状态、资源包生成 |
| M3 | 1-2 周 | 客户端闭环 | Windows 客户端、导入资源包、桌面显示 |
| M4 | 1 周 | 账号与支付 | 登录、订单、支付、权益 |
| M5 | 1-2 周 | 增长模块 | 分享卡、艺术相册、云养广场试验 |

## 2. 团队角色

| 角色 | 责任 |
| --- | --- |
| 产品经理 | 范围、流程、验收、指标 |
| UI/UX | 自有品牌视觉、组件、移动端 |
| 前端 | Web 页面、上传、状态机、支付页 |
| 后端 | API、任务、订单、作品库、存储 |
| AI/图像 | 候选生成、动作生成、质量控制 |
| 客户端 | 桌面窗口、托盘、资源包导入 |
| 测试 | 生成链路、支付链路、安装链路 |
| 运营 | 案例、FAQ、活动、客服 |

## 3. M1 Web MVP 任务

### 前端

- 搭建页面路由。
- 首页。
- 生成工作台。
- 上传组件。
- 候选图展示。
- 套餐选择。
- mock 支付页。
- 作品库。
- 下载说明页。
- FAQ。

### 后端

- 创建宠物任务。
- 上传图片。
- 返回 mock 候选图。
- 创建 mock 订单。
- mock 支付确认。
- 生成 mock 宠物码。
- 返回作品库列表。

### 验收

- 用户可完整跑通从上传到作品库。
- 没有真实支付依赖。
- 所有状态都有错误提示。

## 4. M2 生成服务任务

- 接入真实 AI 生成候选。
- 任务队列。
- 状态轮询。
- 失败重试。
- 生成成本记录。
- 候选质量人工审核入口。
- 资源包打包。

验收：

- 生成失败率可统计。
- 平均生成时间可统计。
- 用户能恢复上次任务。

## 5. M3 客户端任务

- Windows 桌面透明窗口。
- 加载宠物帧图。
- 基础动作循环。
- 拖拽导入 `.petpack`。
- 输入宠物码导入。
- 托盘菜单。
- 退出应用。
- 打包下载。

验收：

- 用户下载后能打开。
- 能导入资源包。
- 桌宠能显示和运动。
- 托盘能退出。

## 6. M4 账号与支付任务

- 邮箱注册登录。
- session。
- 订单表。
- 支付通道。
- 支付回调。
- 支付状态复查。
- 订单取消。
- 生成次数/权益。
- 账号中心。

验收：

- 支付不会重复下单。
- 刷新页面后订单可恢复。
- 支付成功后权益到账。
- 订单和宠物绑定正确。

## 7. M5 增长模块任务

优先级从高到低：

1. 分享卡。
2. 艺术相册免费预览。
3. 艺术相册付费整套。
4. 云养广场只读展示。
5. 云养广场互动。

## 8. 项目管理建议

- 每阶段都必须有可演示版本。
- 不要同时做客户端、支付、社区和艺术相册。
- 每个生成任务必须有日志和状态。
- 支付必须先做防重复订单。
- 客户端安装体验必须单独测试。
