# 客户视角建议与整改记录

审查日期：2026-06-12

## 客户提出的问题

1. 首屏看起来有吸引力，但用户会担心“付钱前能不能先看效果”。
2. 用户上传照片时，不清楚什么照片更容易生成好，也不知道带水印或图库图是否能用。
3. 套餐页强调价格，但对买断制、重复扣款、失败处理的说明不够靠近购买按钮。
4. 支付页像真实收款页，但当前仍是模拟支付，容易让试用客户误会。
5. 生成完成后虽然有宠物码和 `.petpack`，但新用户不一定知道下一步该先下载客户端还是先保存资源包。
6. 下载页展示了客户端入口，但 MVP 阶段还没有正式安装包地址，需要明确状态。
7. 旧前端审查文档仍写着“未接真实 API”，和当前实现状态不一致。
8. 直接打开 `#studio`、`#install` 或在同页切换 hash 时，页面需要可靠刷新到对应模块。
9. 1280px 桌面宽度下顶部账户区可能撑出横向滚动条，影响精致度。

## 已完成整改

1. 首页增加信任承诺区，明确“先看 6 张候选，满意再付费”。
2. 上传区增加照片质量建议，并加入素材授权确认。
3. 套餐区增加买断制、不重复扣款、支付后生成动作包的近场说明。
4. 支付区明确当前为模拟支付，真实支付需要服务端回调验签。
5. 完成页增加下一步说明：下载客户端、导入宠物码或拖入 `.petpack`、作品库保留记录。
6. 下载页增加安装包接入说明，避免用户误判当前客户端成熟度。
7. 更新 `docs/frontend-static-audit.md`，把 API 对接状态和剩余真实化缺口改为当前实际情况。
8. 增加 hash 路由监听，修复同页 hash 切换不刷新目标页面的问题。
9. 增加中等桌面宽度导航压缩规则，消除顶部栏横向溢出。

## 仍建议后续推进

1. 接入真实支付渠道，补齐支付回调、验签、退款和对账。
2. 提供真实 Windows 客户端安装包下载地址，并在下载前展示版本号、文件大小和校验值。
3. 增加用户主动删除上传图、生成图和订单数据的入口。
4. 对明显水印、低清、主体不完整图片增加更强提示或阻断策略。
5. 给 `.petpack` 增加版本号和兼容性字段，避免后续客户端升级后资源包不可用。

## 2026-06-12 动作生成补充

1. 后端动作包扩展为多动作连续帧：待机、向右走、向左走、睡觉、坐下、跳跃、伸懒腰、小跑、开心摇摆。
2. 动作帧统一输出 RGBA PNG，四角 alpha 为 0，前端以棋盘格舞台展示透明背景。
3. 每个动作返回 `label`、`fps`、`loop`、`transparent`、`frameCount` 和 `frames`，便于客户端和网页统一播放。
4. 生成完成页新增动作类型列表，点击任一动作可在页面中循环预览动画。
