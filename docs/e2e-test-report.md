## 发现并修复的问题

### P0：候选图抠图破洞

问题：白色毛发被误判为背景，候选图出现青色洞。

修复：将抠图算法改为从图片边缘 flood-fill 连通背景，再反向生成主体 silhouette，并用 MaxFilter + GaussianBlur 平滑边缘。

### P0：输入表单未真实提交

问题：前端宠物名和性格描述只显示在输入框，提交 API 时仍使用硬编码值。

修复：新增 `state.petName` 和 `state.description`，监听输入事件，并在 `POST /api/pet-jobs` 中提交真实字段。

### P1：水印/授权风险未提示

问题：测试图带明显水印，生成结果会带入水印，但前端没有提示风险。

修复：后端模型特征增加 `qualityWarnings`，前端候选页和套餐页展示图片质量/授权风险提示。

### P1：服务端缺少上传保护

问题：直接调用 API 可绕过前端 8MB 和格式限制，无效图片可能造成 500。

修复：Flask 增加 `MAX_CONTENT_LENGTH`、413 handler、无效图片 400、生成失败 400。

### P1：隐私口径不一致

问题：生成完成后原图仍保留在 uploads。

修复：资源包生成完成后删除上传原图，只保留候选、动作帧、manifest 和 `.petpack`。

## 当前仍需注意

- 当前动作生成是轻量视觉模型 + 程序化动作帧，能跑通业务闭环，但不是最终生产级动画模型。
- 当前支付是 mock 支付，真实上架前需要接真实支付通道和回调验签。
- 当前服务使用 Flask 直接运行，生产流量建议换成 Gunicorn/Nginx 或同等 WSGI 部署。
- 带水印图片当前提示风险但不阻断，正式商用建议增加强制确认或拒绝策略。
